我的Hexo博客搭建经历记录

今天我完成了自己的第一个个人博客搭建，从零开始学习了Hexo\git\gitHub pages\butterfly主题以及markdown写作。

1.配置博客开发环境

这里包括gitNode.js\npm\git bash，刚开始接触这些工具时，我并不了解它们之间的关系，只知道按照教程输入命令，但是在不断遇到问题和解决问题的过程中，我逐渐理解了每一步的作用。并认识了 Hexo 的几个命令：
hexo clean：用于清理之前生成的网站文件，相当于删除旧的缓存和生成结果，让博客重新生成。
hexo g：也就是 hexo generate，用来生成网站文件
hexo s：也就是 hexo server，用来在本地启动博客服务器，通过 localhost:4000 查看自己的网站效果。

2.把博客部署到 GitHub Pages

我了解到这一步是为了让别人也可以通过网址访问我的网站。过程中遇到了 GitHub Pages 404 的问题。我学习到了本地网站和线上网站的区别：localhost:4000 代表只运行在自己电脑上的网站，只有自己能看到。GitHub Pages 部署后的网站才是真正发布到互联网，其他人可以通过网址访问。部署过程中还遇到了等待时间不够、分支选择、用户名大小写等问题，让我理解了网站上线并不是简单复制文件，而是需要正确配置服务器和仓库。

3.安装 Butterfly 主题

这个过程中遇到了第一个比较明显的问题：执行git clone命令时出现了无法连接 GitHub 的错误，一开始以为是命令错误，后来我借助ai发现主要原因是网络连接问题。经过尝试后，我使用把HTTP修改为SSH成功下载了Butterfly主题。这让我认识到：当程序出现错误时，不一定是代码的问题，也可能是网络、环境或者配置的问题，需要根据错误信息判断原因。安装主题后，我修改了_config.yml，让博客使用 Butterfly 主题。然后重新执行：hexo clean，hexo g，hexo s最终成功在浏览器中看到自己的博客页面。

4.修改博客个人信息

修改头像时遇到了一个滑稽的问题：配置文件中写了：avatar:img: /img/mimi.png，但是浏览器访问时失败了，最后发现原因是图片路径错误。Hexo 网站使用的是网页路径，而不是电脑中的文件路径。正确方式是：把图片放在source中的img而不是butterfly中的source的img。结果我又遇到了新的问题，上网查以后我发现在系统中的文件名被隐藏了，也就是我之前在将.jpg的图片修改成.png时把照片变成了.png.jpg所以图片仍旧是.jpg形式，最后我扩展文件名成功修改了图片形式，我以后都会记住这个问题。

5.创建Markdown博客文章

就像你现在看到的这样，我终于创建了source/_posts/qi的第一篇博客.md 学习了 Markdown 的基本格式，例如：

title: 标题
date: 日期
tags:

  • 标签1
  • 标签2

正文内容

这次Hexo博客搭建是我进入编程世界的一次重要实践，也让我第一次感受到从代码到真实网站诞生的完整过程。我相信多年以后我仍然能够犹如现在的这份热情，做自己真正喜欢的事。
